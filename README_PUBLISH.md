# AKWAOS ARG Starter

Статический стартовый модуль для GitHub Pages. Внешние библиотеки не используются.

## Что уже есть

- экран «Запуск системы»;
- обратное размытие логотипа AKWAOS;
- загрузочный trace/мини-консоль;
- Web Audio сигналы без отдельных mp3-файлов;
- плавный переход к рабочему столу;
- окна, которые можно перетаскивать;
- архив файлов;
- терминал с командами;
- карточка Adrian Lamo;
- индекс исследований;
- простая мини-игра CALIBRATE.EXE;
- localStorage для сохранения скрытых состояний;
- 404-страница под будущую ARG-механику.

## Публикация на GitHub Pages

1. Создайте репозиторий.
2. Загрузите содержимое этой папки в корень репозитория.
3. Settings → Pages.
4. Source: Deploy from a branch.
5. Branch: main / root.
6. Сохраните настройки.

Файл `.nojekyll` уже добавлен.

## Важно для ARG

GitHub Pages — статический хостинг. Всё, что вы публикуете в JS/HTML/JSON, технически можно скачать и изучить.

Поэтому настоящие ответы, будущие сюжетные файлы и «секретные» развязки лучше не хранить открытым текстом. Для следующих этапов проекта лучше использовать:
- зашифрованные payload-файлы;
- ключ, который игрок получает из решения загадки;
- проверку по хэшу, а не сравнение с открытым ответом;
- минификацию/обфускацию как дополнительный шум, но не как единственную защиту.

## Структура

- `index.html` — оболочка ОС.
- `assets/styles.css` — CRT/desktop/window UI.
- `assets/app.js` — boot sequence, окна, терминал, мини-игра.
- `assets/icons/` — локальные SVG.
- `404.html` — ARG-совместимая страница ошибки.
- `_MASTER_NOT_PUBLISH.md` — заметки для автора. НЕ ЗАГРУЖАТЬ В ПУБЛИЧНЫЙ РЕПОЗИТОРИЙ.

## Следующий логичный этап

Вынести сюжетные сущности в отдельную систему данных:
`chapters → triggers → files → flags → encrypted payloads`.

Так можно выдавать информацию строго по цепочке, а не показывать весь сюжет сразу.
